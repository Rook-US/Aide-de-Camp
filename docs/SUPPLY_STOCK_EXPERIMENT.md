# Test 6: existing infantry supply stock

Prepared 8 October 2026, local only. This is a disposable 1.142 **existing-unit** test, not an ADC supply edit or creation control. The copied save is `Campaigns/001/G/ADC-TEST-6-INFANTRY-HALF-STOCK`, sourced from the player's confirmed game resave `Save7_10_2026_22_35_17`. The source is unchanged.

The test resolves the unique `ADC Test 1-1 Infantry` `paths.dat` record by the game's four-part identity: name, abbreviation, runtime type 0, and commander 91. The full counted path parser locates its four saved `supplyinstock` values. The source has stock `(999.1487,1000,1000,1000)` and `regiments.dat` total men 1000. The test changes only stock indexes **0 and 2** to 500, yielding `(500,1000,500,1000)`. The installed `Regiment.GetAvgSupplyState` uses indexes 0 and 2 for type 0 and divides each by live strength; if strength remains 1000 and no load-time recalculation occurs, the method's result should be 0.5. This is a **prediction to test**, not an established game UI percentage or initial-supply setting. Ammunition, consumption, `supplystate`, all other unit data, and all other `paths.dat` records are untouched. `scenario.dat` changes only the label to **ADC Test 6 - Infantry Half Stock**.

[`Build-SupplyStockExperiment.ps1`](../scripts/Build-SupplyStockExperiment.ps1) refuses to overwrite the test copy, checks the exact source stock and unit strength, requires one matching four-part path identity, and verifies exactly two changed `paths.dat` lines and only two changed files. ADC reload checks passed on the input: 18 creation-resave checks and nine town checks.

**Test-design correction, 8 October 2026:** The player reports that the campaign map shows supply when selecting an independent command, usually a vanilla Army or Corps HQ, but does not expose a brigade's supply panel there. The installed game's manual, pages 90 and 113–114, describes the selectable army/corps/garrison panel. It distinguishes the main **Supplies** percentage (the incoming flow relative to current consumption) from icons for **carried stores**. `Regiment.UpdateSupplyIcon` reads individual `supplyinstock`, while `BattleUnits.UpdateCampaignSupplyStates` uses top supply units' `groupsupplystate` and stock. Therefore the predicted `GetAvgSupplyState()` result of 0.5 for this infantry is **not** a prediction that an HQ's visible flow percentage will read 50%. The earlier request to inspect a brigade's campaign-map percentage was unsuitable. This copy remains untested in game; no supply write rule follows from it. The next UI experiment must target a selected HQ and distinguish flow from carried stores.

## Paused and time-advanced game results

The player loaded this copy and provided two 1.142 game saves: `Save8_10_2026_14_18_4`, labeled **ADC Test 6 - Paused**, and `Save8_10_2026_14_18_18`, labeled **ADC Test 6 - Unpaused**. The unique four-value path identity was retained. The paused save kept the exact inserted stock `(500,1000,500,1000)` and flow `1`. After time advanced, the game wrote stock `(556.0485,1000,677.2684,1000)` and still wrote flow `1`. The game therefore **accepted reduced stock**, then replenished indexes 0 and 2 during campaign time. This is a separate mechanism from the HQ incoming-flow percentage demonstrated in [Test 8](HQ_SUPPLY_FLOW_EXPERIMENT.md).

The read-only [parent-chain audit](../scripts/Trace-UnitSupplyHierarchy.ps1) follows the target's current-save parent IDs rather than matching names across files. In the copied input, `1st Infantry Division` (native tier 15) had group stores `(100,92.07277,100,100)` and I. CORPS (native tier 16) had `(100,78.93917,100,100)`. In the paused resave the division stores were `(98.62591,92.07277,99.10549,100)` while I. CORPS remained `(100,78.93917,100,100)`. After time advanced, the division stores were `(98.85064,93.05432,100,100)` and I. CORPS `(100,81.1623,100,100)`. The immediate parent `1-1 INFBDE` (native tier 14) was saved with four zero group-store values in both game resaves, so these values must not be presented as a universal store percentage for every displayed tier. The saved changes support a subordinate-stock contribution to higher command summaries but do not by themselves prove a distribution formula or that I. CORPS directly refilled this infantry unit.

The full-file [path comparison](../scripts/Compare-CampaignSupplyRecords.ps1) matched all 814 path records by the game's four-value identity between the two resaves; 52 flow values and 475 stock arrays changed after time advanced. Both game saves passed 18 ADC creation-resave checks and nine town checks. This validates **direct stock editing for this existing 1.142 infantry unit** as a game-accepted input. It does not yet validate a user-selected starting supply for a **new** combat unit: the controlled creation route omits a new path record and the game creates full stock. Creating a reduced-stock unit in one operation would need a separately validated new path record or another tested mechanism. No production supply control is offered from this experiment alone.
