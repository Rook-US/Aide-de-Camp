# Existing-unit supply stock editing in ADC

Local implementation, 8 October 2026, for the installed game and save version **1.142**. This is an **existing combat unit** editor. [Test 9](DIVISION_SUPPLY_STOCK_EXPERIMENT.md) supplied the game load, paused resave, and time-advanced resave evidence: all 72 tested stock values survived paused load exactly; the game's HQ stores recalculated from the affected units; advancing time replenished them. New-unit starting supply, command reserves, and the independent incoming-flow percentage are not editable here.

Select one or more land combat units in Armies or Garrisons and choose **Edit Supplies**, or use **Edit Supply Stock** from one unit's detail editor. The four categories are small-arms ammunition, artillery ammunition, provisions, and forage. ADC enables only the categories used by each unit type: infantry uses small-arms ammunition and provisions; cavalry uses small-arms ammunition, provisions, and forage; artillery uses artillery ammunition, provisions, and forage. The other saved slots are preserved byte-for-byte. A mixed selection edits only the units that use the entered category. Empty input leaves that category unchanged.

The default input mode is **percent of active unit strength**, matching `Regiment.GetAvgSupplyState`'s unit-level divisor. The UI setting `supply.stock.rawValues` selects exact saved amounts instead; changing the mode in the dialog clears entered drafts to avoid reinterpreting them. The current amount is shown in the chosen mode. Percent input is 0–100. Raw input must be finite, nonnegative, and no higher than the greater of the game's observed campaign refill target (`Total_Men + Wounded`) or that slot's already saved amount. Values above 100% of active strength may exist in game saves; ADC shows them without clipping. The game's HQ category percentages can differ slightly because their denominator and aggregation differ.

The validated changes stage through `EditSession` as one undoable operation. Save writes only affected `paths.dat` fields using ADC's whole-save backup, temporary-file round trip, hash recheck, and rollback path. The writer requires a unique four-field path identity, a fully parsed four-slot record, and version 1.142. It rejects malformed/unsupported path data and a simultaneous stock plus strength edit; save strength first so the percentage basis is unambiguous. It leaves all `groups.dat` store fields untouched; the game recalculates them on load as observed in Test 9. A direct change to main incoming-flow `supplystate` is not offered because [Test 8](HQ_SUPPLY_FLOW_EXPERIMENT.md) showed it is transient.

Verification on a disposable copy of the player's **paused Test 9 game resave** passed 15 focused checks: percentage conversion and type relevance across infantry, cavalry, and artillery; one-step undo/redo; stock-only file changes; backup retention; ADC reload; rejection of nonfinite and over-target values, malformed or ambiguous stock, and unsupported version. The standard service suite passed 178 checks and the Windows UI suite passed 590 checks, including opening the new dialog and previewing a percentage edit. No live game save was changed by the production writer test. The production writer's output has not separately been loaded in the game; the Test 9 copy established game acceptance of the same `paths.dat` stock fields, and the focused test verifies ADC changes only those fields.
