# Build, verify, and package

Use Windows x64 and a .NET 8 SDK. `global.json` permits newer .NET 8 feature-band SDKs. No game files are required to build or run the synthetic verification suites.

From the repository root in PowerShell:

```powershell
dotnet build AideDeCamp.sln -c Release
$env:AIDE_DE_CAMP_DATA = Join-Path $PWD 'artifacts/test-preferences'
dotnet run --project tests/Verification -c Release
dotnet run --project tests/UiVerification -c Release
dotnet run --project tests/UiVerification -c Release -- --tree-checks artifacts/tree-after
dotnet run --project tests/UiVerification -c Release -- --tree-performance artifacts/tree-performance
```

The UI suite opens test windows and requires a Windows desktop session. `AIDE_DE_CAMP_DATA` isolates test preferences from your personal application settings. Test programs also accept optional local campaign/configuration paths; consult their argument handling before using real data. Do not commit that data or output containing personal paths.

## Portable distribution

```powershell
./scripts/Package.ps1
./scripts/Test-Package.ps1 -Archive ./artifacts/Aide-de-Camp-0.8.15-win-x64.zip
```

The package bundles .NET and Windows Desktop into one self-contained executable, without trimming. Native and managed runtime content is extracted to the .NET bundle cache when needed. Only the EXE and README are files in the release root; documentation and notices live in subfolders. Source/debug files are excluded. The script pins runtime 8.0.30; use `-RuntimeVersion` to deliberately update it and rerun verification.

Packaging requires a fresh staging directory to avoid including stale files. Archive prior artifacts or use a fresh checkout before repeating a package build. The package check verifies root contents and absence of source files, extracts the ZIP into a unique directory, opens the branded WPF window with isolated preferences, and verifies that the runtime came from the executable's bundle. It does not edit a campaign or prove compatibility with every clean Windows installation.

GitHub Actions builds and verifies the package on Windows and uploads the ZIP and SHA-256 checksum as workflow artifacts. For a public release, attach those files to a versioned GitHub Release and mark alpha and beta builds as prereleases. The source-code archives generated by GitHub are separate from the runnable ZIP.
