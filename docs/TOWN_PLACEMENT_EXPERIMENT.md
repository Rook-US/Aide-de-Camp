# Test 3: existing independent command at a selected town

Prepared 8 October 2026, local only. This is a **controlled placement experiment**, not a supported ADC Create or Move operation. The input copy is `Campaigns/001/G/ADC-TEST-3-I-CORPS-NEW-YORK`, made from the player's confirmed 1.142 game resave `Save7_10_2026_22_35_17`. The source save was not edited.

The selected existing command is the unique Union `I. CORPS` with commander ID 0, root parent `-1`, saved native tier 16, and one `battledata.dat` group deployment. It has no fort reference. The verified 1861 town record for **New York** has owner 0, state ID 27, world position `(1777, 489.2545, -475)`. The game's `CreateBattleDataFile` maps world x/z to deployment x/**negative world z**. Its original deployment map coordinates were `(1608.989, 729.1851)`; this copy changes only that record's deployment x/z to `(1777, 475)`. No group, combat, path, garrison, army-group, town, or version record was edited. `scenario.dat` label was changed to **ADC Test 3 - I Corps to New York** so the copy is recognizable in the game's load list.

The complete `paths.dat` parser found one matching runtime identity (`I. CORPS`, blank abbreviation, runtime type 16, commander 0). Its saved transfer position, patrol start, and theater position are all `(0, 0, 0)` in the copied input. The experiment leaves them unchanged; comparing the game's resave will show whether it fills or changes any of them after placing the command.

[`Build-TownPlacementExperiment.py`](../scripts/Build-TownPlacementExperiment.py) refuses to overwrite an existing test, validates source version/date, complete group and battledata counts, the command's saved identity/hierarchy, the town's exact name/position/owner against the verified texture map and save, and the precise two-field deployment diff. It checks that only `battledata.dat` and the label file differ after copying. ADC reloaded the copy successfully: 18 existing game-resave integrity checks and nine town/location checks passed.

## Game load and resave result

The player loaded the test and confirmed **I. CORPS HQ appeared at New York City**. Only the HQ moved; its subordinate units remained where they were. The player accidentally overwrote the test folder with the game's manual resave, now labeled **ADC Test 3 - Confirmed**. The original source `Save7_10_2026_22_35_17` remains intact, and the exact prepared two-field input plus label is reproducible by the builder script and recorded in the ignored local manifest `artifacts/town-placement-experiment-2026-10-08.json`.

The read-only [`Check-TownPlacementResave.py`](../scripts/Check-TownPlacementResave.py) resolved the same root command by name, commander, faction, parent, and saved native tier in the game-written resave. Its unique `battledata.dat` group deployment remains `(1777, 475)`, exactly New York's saved map coordinates. [`Audit-TownPlacementResult.py`](../scripts/Audit-TownPlacementResult.py) resolved descendant groups through current-save parent IDs, not line numbers or names: 21 descendant commands and 57 attached combat units remained under I. CORPS. The four directly subordinate divisions still have their previous deployment positions, and none of the 57 combat units has an independent `battledata.dat` deployment. The complete `paths.dat` parser found 814 records in both saves; I. CORPS's transfer, patrol, and theater positions remain `(0,0,0)` after the game resave. ADC reloaded the resave: all 18 existing game-resave checks and all nine town checks passed.

This proves a **narrow 1.142 placement rule for one already existing independent command**: changing its unique `battledata.dat` group deployment x/z to a verified town position moved that HQ in game and survived a game-written resave. It did **not** move subordinate command deployments. A future move feature must make that behavior explicit or validate a separate multi-command operation. This experiment did not create a new command record, prove placement for an empty new root, test other factions or native tiers, or establish the full transactional writer. No production placement or Create write control is offered yet.
