# Test 11: a new infantry unit with half starting stock

Prepared locally on 8 October 2026 for the installed game and save version **1.142**. This is a disposable game-load experiment, **not** an ADC new-unit supply writer. The source is the player's paused save `Save8_10_2026_19_59_24`; the test copy is `Campaigns/001/G/ADC-TEST-11-NEW-INFANTRY-HALF-STOCK`, labeled **ADC Test 11 - New Infantry Half Stock**. [`Build-NewUnitHalfStockExperiment.py`](../scripts/Build-NewUnitHalfStockExperiment.py) refuses to overwrite the test folder and leaves the source untouched.

The experiment appends one counted 39-line infantry record. Its new saved ID is the next ordinal 526; its explicit numeric parent is existing `1-1 INFBDE` group 71, with native tier 14 and commander 2. The new combat unit has native tier 13, 1,000 men, Springfield M1861 weapon ID 14, Maryland home-state ID 17, and existing unused Union commander ID 97 (Thomas W. Sweeny). These branch, weapon, strength, state, and parent values match the already accepted Test 2 infantry combination, while the officer and displayed name are new test inputs.

Unlike Test 2, this input also appends a **complete counted `paths.dat` record**. Its 250-line no-order structure comes from the game's own resave of the Test 2 newly created infantry in this same paused campaign. The builder fully parses every source path record, resolves that one by the game's four-field identity, verifies its variable-section structure, then changes the new record's four identity fields and its four `supplyinstock` amounts. The new amounts are `(500,1000,500,1000)`: 50% of active strength for infantry's relevant small-arms and provisions slots, with the inactive artillery and forage slots at the observed full-strength baseline. The script does **not** use an absolute source line as a persistent identity. Other path fields retain the sampled game-written state as a **test hypothesis**; their field meanings are traced in [the companion-data map](ADDITIONAL_UNIT_DATA_MAP.md), but copying that state to a second newly created unit has not yet passed the game gate.

Only `regiments.dat`, `paths.dat`, and the visible `scenario.dat` label differ from the source. Counts, contiguous IDs, the new parent, unique existing commander, full path parse, four-field cross-file match, exact stock values, and unlisted-file hashes were checked before offering the copy to the game. ADC independently loaded it and passed four focused input checks. In this input, `armygrouprefs.dat` still has the old combat count; the earlier Test 2 established that omission for a new combat record is accepted in version 1.142, but the combined **new path plus new regiment** case is untested.

## Game-written paused resave

The player loaded Test 11 and made paused manual save `Save8_10_2026_21_10_8`, labeled **ADC Test 11 - Paused**. The campaign view did not expose this combat unit's own supply display; it showed the parent command's supply instead. The player did not explicitly confirm the new unit's commander or hierarchy visually, so those are established here by the game-written records and ADC reload.

Five checks passed on the resave: version 1.142; the named unit with commander 97 still has parent **1-1 INFBDE**, infantry branch/native tier, Springfield M1861 weapon, 1,000 men, and Maryland home state; every live command and unit has one fully parsed path record; the new unit has one exact four-field path identity; its four `supplyinstock` values remain **`(500,1000,500,1000)`**; and `armygrouprefs.dat` contains complete regenerated counts. The game changed the unit's list-ordinal ID from input `526` to resaved `150`, demonstrating why persistent joins must resolve names/type/commander and current-save parent IDs rather than hold the input ordinal. The complete new 250-line path retained its count-delimited structure. Compared by the four-field identity, only the path's campaign timestamp (relative offset 31, `0.6881952` to `0.6882216`) and its service-history text (offset 237, updated from the corresponding regiment record) changed; the four stock lines did not.

This validates one **new 1.142 infantry unit under the tested brigade**, with this game-written no-order path structure and these explicit starting stock values, through a paused game load and resave. It does not establish a general path template for other branches, parent tiers, movement states, or versions. A production writer must still construct and validate the complete record from traced fields, coordinate its four-field identity with `regiments.dat`, and include it in ADC's backup, transaction, and undo path. **Unable to proceed** with a general editable-supply creation control until those pieces and the other requested combinations pass their gates. The existing-unit stock editor remains supported separately.
